## Team and workflow

- Bigger work: `$intake` (you act as PM/product owner: interview, design, workplan), then a fresh chat runs `$uw <workplan dir>` (you act as orchestrator: assign, review, check in). Small tasks outside that flow: just do them, delegating where it clearly saves effort.
- Agents: `fe-dev` (UI code), `be-dev` (data/backend code, debugging), `qa` (tests, checks, failure analysis), `ui-ux` (design with oil-ui, then build/polish with impeccable), `docs`, `devops` (git/GitHub/Supabase/Vercel), `explorer` (search, tracing how code works), `reviewer` (diff review). Stack notes are skills: `$kotlin-android`, `$web-ts`.
- Models: `fe-dev`, `be-dev`, `qa`, `docs`, `devops` run on gpt-6.1-sol; `ui-ux` runs on gpt-6-astra (both fixed in the agent files, never changed). `explorer` and `reviewer` run on whatever model the orchestrator picks. The orchestrator picks reasoning effort for every spawn.
- Impeccable and oil-ui are for UI work only. Ponytail only when I explicitly ask for it by name or command; this applies to subagents too.
- Long commands get a time limit from a hook (`~/.codex/hooks/bash-timeout.py`); when it hands you a wrapped command, run that instead. A TIMED OUT message is something to report, not wait on; add `# timeout=90m` to a command that legitimately needs longer.
- Project AGENTS.md/CLAUDE.md rules override skill instructions.

## Git

- Never commit, push, or open a PR until I've explicitly approved it AND given the exact commit message (or PR title/body). Propose one if useful, but wait for mine. This applies to every agent and overrides any skill.
- No attribution or co-author trailers in commits or PRs.

## Projects stay free of AI traces

- Nothing AI-related goes into a project repo: no `.claude/`, `.codex/`, `.agents/`, `.oil-ui/`, CLAUDE.md/AGENTS.md (unless the project already tracks one), plans, specs, mockups, agent notes, or comments like "designed with oil-ui" / "generated by Claude/Codex".
- Files that must exist locally are hidden via `.git/info/exclude`, never `.gitignore`; `.gitignore` must not mention them.
- Workplans (spec, plan, overview, your-plan, progress, what-changed, design/) live in `~/.codex/workplans/<repo-name>/<DD-MM-YYYY>-<slug>/` and are never referenced from project files.
